# MQTT IoT Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a React Native + TypeScript clone of the original app with multiple brokers and on-demand tiles of six types.

**Architecture:** Pure domain logic (`src/domain`) is separated from MQTT transport (`src/mqtt`), persistence (`src/store`) and UI (`src/ui`). Logic and the MQTT wrapper are tested in Node with Jest; the UI is verified on the real phone with adb.

**Tech Stack:** Expo SDK (dev build), React Native, TypeScript, Jest, react-navigation, zustand, AsyncStorage, mqtt.js, react-native-tcp-socket.

**Spec:** `docs/superpowers/specs/2026-10-24-mqtt-iot-design.md`


## Execution status (updated at the end of the work)

All tasks were completed; where the work differed from this plan, the code and `docs/superpowers/verification.md` are
authoritative. Deviations, each with its reason:

- **MQTT client** (Task 5): a small MQTT 3.1.1 client of our own (`src/mqtt`) instead of `mqtt.js`. mqtt.js needs Node
  stream/net polyfills on Hermes; the own client runs the same code in Jest (against `test.mosquitto.org`) and on the phone.
- **Data model** (Task 2/4): mirrors the original's Gson classes (names, integer type ids, ARGB colors, real defaults)
  instead of the invented model drafted here, so import/export is interchangeable (proved with a fixture exported by
  the original app).
- **Tap dialogs, forms, grid, texts, icons, colors** (Tasks 7-10): taken from the decoded APK (layouts, strings, 438 vector
  icons, `metric_colors`), see `fidelity-ledger.md`.
- **Scripts** (Task 11): documented `event` / `app` API on Hermes' indirect `eval` (Hermes has no `with`).
- **Notification tile / background** (Task 12): Notifee (local notifications + foreground service, no Firebase) rather
  than `expo-notifications`, which pulls Firebase Messaging on Android.
- **Dark/light theme**: requested and then withdrawn by the user; not built (faithful copy).
- **Window**: classic non edge-to-edge window with `adjustResize`, as the original (needed for correct keyboard handling).

## Global Constraints

- No Firebase/FCM/Google services anywhere; notifications are local only.
- Fidelity: UI texts, colors, dimensions and icons come from the extracted original (Task 0 ledger), not from taste.
- Code, comments, identifiers and commit messages in English. Commits plain: no co-author trailer, no "Generated with" line.
- Broker default port 1883; default client id `mqttiot-` + 8 hex chars; import/export default topic `metrics/exchange`; Image default reload interval 5 s; Range defaults min 0, max 100, precision 0.
- Tile types (exact ids): `text`, `switch`, `range`, `multi`, `image`, `color`, and (added by request) `notification`. Menu labels: "Text", "Switch/button", "Range/progress", "Multi choice", "Image", "Color".
- QoS values 0, 1, 2. Validation broker: `test.mosquitto.org` (1883 tcp, 8080 ws).
- Android only is built and verified. Use JDK 21 for Gradle (`JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64`), SDK at `~/Android/Sdk`.

## Review Focus

- Empty or whitespace-only payload on a Switch tile: stays in its last state, no crash.
- Invalid JSONPath or non-JSON payload with a JSONPath set: tile shows the raw error state, app does not crash.
- Range payload that is not a number, or outside min..max: clamped progress, no NaN rendered.
- Broker unreachable / wrong credentials: visible "disconnected" status with retry, not a silent hang.
- Throwing or infinite-looping user script: caught; tile keeps working with the error message shown.

### Task 4: Tile state logic

**Files:** Create `src/domain/tileState.ts`; Test `src/domain/tileState.test.ts`.

**Consumes:** `Metric`, `extractJsonPath`.

**Produces:**
- `interface TileState { lastPayload: string|null; value: string|null; error: string|null; lastActivity: number|null; pending: boolean; pendingSince: number|null; changed: boolean }`, `initialTileState(): TileState`.
- `applyMessage(metric: Metric, state: TileState, payload: string, now: number): TileState` — clears `pending`, sets `changed = payload !== lastPayload`, `lastActivity = now`; with `jsonPath` set stores the extracted value (error → `value ''`, `error 'JSON path error'`); for `switch`, ignores payloads whose (extracted else raw) value equals neither `payloadOn` nor `payloadOff`.

- `rangeProgress(metric: RangeMetric, state: TileState): number` (percentage 0..100 as in the original `getProgress`), `rangeLabel(metric, state): string` (`prefix + %.<precision>f + postfix`, of the progress, or of the value when `displayPayloadValue`).
- `enterPending(state, now)`, `isPendingExpired(metric, state, now): boolean`.
