# Widget UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Replace the original tile look with the reference app's widget UI (theme tokens, 24-column widget grid, widget box picker, widget views, app bars) while keeping MQTT, the metric model and scripting underneath.

**Architecture:** Each stored metric gets an optional `widget` kind and optional cell geometry `gx, gy, gw, gh` (24-column grid). The metric type (1-7) and all MQTT logic stay unchanged; a widget kind is a presentation and interaction variant of a metric type. Metrics without `widget` or geometry (old data) get a kind derived from the type and are auto-placed.

**Tech Stack:** React Native 0.88, TypeScript, zustand, PanResponder, react-native-svg (gauges), existing icon font.

**Spec:** `docs/superpowers/specs/ui-reference.md`

## Global Constraints

- Android only; no dependency additions beyond what is installed.
- Code, comments, commits in English; commits plain (no trailers).
- No mention of the reference app's name anywhere in the repo.
- Existing MQTT behavior, import/export JSON and scripts keep working (jest stays green).
- Grid: 24 columns, square cells, widget card = surface, 1 dp stroke neutral3, radius 0, padding 4 dp.
- Tokens, fonts and sizes exactly as in the spec (section numbers referenced per task).

## Review Focus

- Old saved tiles (no widget, no geometry) still appear, auto-placed without overlap.
- Moving or resizing never creates overlapping widgets or leaves the 24 columns.
- A widget with an empty topic renders without crashing.
- Non-numeric payloads do not break Slider/Gauge/Level (show min).
- Light and dark system themes are both readable.
